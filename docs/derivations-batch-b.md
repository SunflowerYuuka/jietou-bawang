# 数值推导 — 批次 B（`astrum:suzume` / `astrum:misogi` / `astrum:kyoka` / `astrum:rino` / `astrum:ayane` / `astrum:yui`）

这份文件是 `docs/balance-derivation.md` 的**续篇**，只覆盖批次 B 的六个角色，格式与口径与那份文件**完全相同**：
每一条数字都能从 bwiki 的系数重算，重算不了的东西写进「没有对应机制」的表里，不静默丢弃。
`docs/balance-derivation.md` 本身**没有改动**（它由人类集中维护）。

## 0. 口径：与 §14.1 同一个参考点、同一个锚点

权威数据是 `K:\AI\Minecraft\assets\bwiki_按角色\<id>_<name>\角色数据.json`。每一招都是一条公式。

| 参数 | 值 | 出处 |
|---|---|---|
| 参考等级 | **208** | `balance-derivation.md` §14.1 |
| 参考攻击力 / 魔法攻击力 | **2000** | 同上 |
| 锚点 | 姬塔 UB `4.8A+60+60L` = **22140** → **20.0** | 同上 |

所以整份文件只有两条重算公式：

```
伤害     值     = 20.0 × raw / 22140        // raw = a×2000 + b×(1+208) = 2000a + 209b，保留一位小数
```

```
回复 / 护盾   u = 20.0 × raw / 22140
              档位 = clamp(round(u / 4), 1, 5)     // 一档 = 参考血条(20)的 20%，见 §14.3
```

```
百分比增益   物理攻击  档位 = clamp(round(raw / (0.20×2000)), 1, 5) = clamp(round(raw/400), 1, 5)
             魔法攻击  档位 = clamp(round(raw / (0.26×2000)), 1, 5) = clamp(round(raw/520), 1, 5)   // §17.1
             物理/魔防 档位 = clamp(round(raw / (0.12×2000)), 1, 5) = clamp(round(raw/240), 1, 5)
             防御下降  档位 = clamp(round(raw / (0.20×2000)), 1, 4) = clamp(round(raw/400), 1, 4)
```

`raw = 2000a + 209b` 是因为 `b + b×L` 在 L=208 时就是 `209b`。文档里每一行都写出了 raw，所以任何一个数字
都能手算复核。

## 1. 两处共用的**设计值**（不是换算，先说清楚）

### 1.1 半径：bwiki 的「范围 N 码」→ 本 mod 的格数

bwiki 写的是战斗场上的码数（300 / 375 / 900 / 1100 / 1250 / 13000），本 mod 写的是格数。仓库里唯一已有的映射
是凯露的**范围 900 码 → `splash` 半径 4.0**，以及她「敵全体」→ UB `radius 6.0`。本批次沿用并补全成一张表：

| bwiki | 本 mod | 依据 |
|---|---|---|
| 13000（全屏） | **16.0** | 超过这个数没有意义：`AllySelector` 的队伍范围远小于它 |
| 1100 – 1300（大范围） | **6.0** | 凯露「敵全体」= 6.0，同一个量级 |
| 900（中范围） | **4.0** | 凯露 专属 900 → 4.0，**唯一一条既有先例** |
| 300 – 500（小范围） | **3.0** | 严格按 900→4.0 的比例（码/225）会得到 1.3 格，比近战判定还小 —— 那不是「范围技能」，是单体。3.0 是「站在目标旁边的身体也在里面」的最小值，**设计值** |

「味方全体」没有码数，一律写 **8.0**（`AttackBuffs.PARTY_RADIUS_DEFAULT` 的同一个数，`docs/balance-derivation.md` §4）。

### 1.2 原版效果（`apply_effect`）的等级：小/中/大 → 1/2/4

本 mod 没有「敌人攻击力下降」这个 `EffectType`，六个角色里只有三个人需要它（未奏希、优衣、绫音需要的是减速）。
能表达它的原版效果只有一个：`minecraft:weakness`（每级 **−4 点攻击力**，`ADD_VALUE`）。等级沿用
`docs/balance-derivation.md` §11 与 §7.2 已经定下的形容词阶梯：

```
小幅 = 1 级      中幅 = 1 级      大幅 = 2 级      特大幅度 = 4 级
```

**这是近似，必须说出来**：原版是**固定点数**、bwiki 是**百分比**，所以「公式值」不可能换算成等级 ——
未奏希 6★UB 的 `30+30L = 6270` 在她的面板上约 313%，而原版 4 级只有 −16 点。等级取的是**形容词**，
不是那个百分比。写在数据里的 `_notes` 也写了同一句话。

**「行动速度变为原本的 0.8 倍」为什么不是 `HASTE`。** 任务书给的提示是「绫音有行动速度条款 → `HASTE`」，
但**方向反了**：`HASTE` 是**加**速、而且 `EffectType.PARTY_SCOPED` 把它钉在**自己阵营**上（`reachesParty() = true`），
所以对敌人用 `haste` 既会把减速变成加速，也会把一个「味方全体」效果写到受害者身上（`UbEffect.mismatch` 会拒绝）。
诚实的落法是 `apply_effect` + `minecraft:slowness`（amplifier 0 = −15% 移速）：方向对了，缺的是「攻速」那一半 ——
与 `docs/balance-derivation.md` §10 当年用 `minecraft:speed` 近似「行动速度」时**同一个缺口**，只是这次是反向。
0.8 倍 ≈ −20%，原版每级 −15%，取 0 级。

好感阶梯：技能1 有专属（tier2 = 噗吉破碎击+）；技能2 无升级（`是否二专: 否`）；EX 有 `+`。没有 6★ 改名。
