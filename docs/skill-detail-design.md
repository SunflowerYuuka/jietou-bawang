# 技能详情页设计

> 这份文件是给实现者的规格。角色册右下角那一小块技能列表改成「一个按钮」，点开进这个页面。

## 为什么改

现在技能挤在角色册右下角的一小块（compact 档只有 2 行），佩可莉姆 6 个技能一次只能看 1 个 + 一个「+5」。加翻页只是缓解，真正的问题是**那块地方装不下**。

## 入口

角色册右下角原技能区的位置，改成**一个按钮**：

```
┌──────────────────┐
│  [图标] 技能详情  >│
└──────────────────┘
```

- 按钮占原来技能区那块矩形
- 点击 → 打开技能详情页（同一个 Screen 内切模式，不是新开 Screen —— 复用九宫格框和主题色）
- 按 `Esc` 返回角色册

## 详情页布局

用户给的格式：

```
技能名1  |  技能名2  |  技能名3
效果     |  效果     |  效果
效果     |  效果     |  效果
效果     |  效果     |  效果
技能名4
效果
效果
效果
```

翻译成实现：

- **多列**，每列一个技能
- 每个技能列内：**技能名**（一行）+ **效果行**（每行一个效果）
- 列宽等分，列数 = `floor(可用宽度 / 最小列宽)`
- 技能多于列数时**换行**（第二排技能从左边重新开始）
- 每个技能列的高度 = 名字 + 效果行数 × 行高，**按最高的一列对齐**

### 技能名显示

| 状态 | 显示 |
|---|---|
| 基础 | `广域斩击` |
| 好感二阶 | `广域斩击+` |
| 好感三阶（改名） | `黄金耀光` |
| 未解锁的更高档 | **灰色**显示（让玩家知道后面还有） |

**用现有数据**：`AffectionDef.skills[].baseName / tier2.name / tier3.name`，别另建一套。

### 效果行内容

每行一个效果，格式：

```
[图标] 效果名  档位
```

例如：

```
[举拳] 攻击提升  III
[火焰] 充能      +
```

**档位显示** = 声明的 tier + 等级档位加成，封顶后的实际值。

### 点击技能查看数值

点某个技能列 → 该列下方（或弹出小面板）显示**数值明细**：

```
广域斩击
  伤害    9.4
  充能    +20
  队友充能 +10 (半径 8)
```

**数值来源**：`effectParams` 里的实际字段，按效果类型分别格式化。不要写死文案，从 `EffectType` + params 生成。

## 需要处理的技术点

1. **布局计算要能单测**：给定技能数和面板尺寸，算出列数、每列位置、换行点 —— 纯函数，像 `BookLayout` 那样。**不要写在渲染方法里。**
2. **点击命中测试**：鼠标坐标 → 哪个技能列。同样单独成纯函数。
3. **滚动**：技能很多时（比如将来 8 个），整个详情页内容可滚动。滚轮只在这一页生效，不抢角色册的滚轮。
4. **两档布局尺寸**都要能放下（compact 320×240 / comfortable 更大）。

## 不要做的事

- **不要新开 Screen 类**：复用 `CharacterBookScreen`，加一个 `mode` 字段（`ROSTER` / `SKILL_DETAIL`）。
- **不要另写一套九宫格**：用现有的面板绘制。
- **不要写死技能名或效果文案**：全部从 `CharacterDef` 读。
- **不要在渲染里算布局**：抽成纯函数并测试。

## 验证

- 单测：列数/换行/每列矩形的纯函数；点击命中；8 个技能时换行正确；compact 档能放下。
- 日志证明：打开详情页、点击技能、返回角色册三个动作都被执行。
- **视觉效果只能人看**：字体大小、列宽是否够读、点开数值面板的位置。
