## C0. 共用的换算（全部来自 §14，不新增）

| 项 | 公式 | 出处 |
|---|---|---|
| 参考点 | 等级 **208**、攻击力 / 魔法攻击力 **2000** | §14.1 |
| 锚点 | 姬塔 UB `4.8×2000+60+60×208 = 22140 → 20.0` | §14.1 |
| 伤害 | `值 = round1(20.0 × 公式(参考点) / 22140)` | §14.2 |
| 回复 / 护盾 | `u = 20.0 × 公式 / 22140`；`占比 = u/20`；`档位 = clamp(round(u/4), 1, 5)` | §14.3 |
| 攻击提升 | `档位 = clamp(round(公式值 / 400), 1, 5)`（一档 = 20% × 2000） | §14.4 |
| 防御提升 | `档位 = clamp(round(公式值 / 240), 1, 5)`（一档 = 12% × 2000） | §14.4 |
| 防御下降 | `档位 = clamp(round(公式值 / 400), 1, 4)` | §14.4 |
| 技能值 | `1 充能点 = 10 TP`（游戏 1000 点气槽 → 本 mod 100 点） | §14.5 |
| 技能值上升 | 「技能值上升 N」是**百分比**：`档位 = clamp(round(N / 25), 1, 5)`（CHARGE_RATE_UP 每档 +25%） | §18 / 本文件 C5 |

**半径**：本 mod 没有「游戏单位 → 格」的换算，沿用已落盘的三档写法 —— 「自身」= `0.0`，
「味方全体」（含半径 150/200/250/300 这类） = 队友默认 `8.0`，敌方全体（含 900） = `6.0`
（凯露的全体 UB 用的就是 6.0）。这不是新规则，是把 bwiki 的措辞映射到已有的三个值。

**`dimension`**（同 tick 递减的分组）：静流 / 望 / 千歌 分别是三个不同的承伤与支援面 —— 静流
`survival`（屏障与回复）、望 `survival`（挑衅与护盾）、纺希 `control`（束缚与位移）、千歌 `resource`
（纯支援：回复 + 召唤 + 攻击提升，零伤害技能）、克莉丝提娜 `output`（纯物理输出）。三人都落
`survival` 会让她们互相递减，这是**有意的后果**（批次 C 的防御角色确实多），不是笔误。

**为什么无敌没有写成 `ally_effect` + `minecraft:resistance` amp 4。**
任务书写的是「无敌 → `APPLY_EFFECT` + `minecraft:resistance` amplifier 4」，而 §18.5 的「无敌 = 抗性五」
也确实是这条式子（等级 5 = 100% 减伤）。但**它挂不到 UB 上**，两个理由都是结构性的：

1. `UbEffect` 的 `effectParams` 是 `TieredParams` —— 只有 `tier` / `seconds` / `radius`，**没有 vanilla 效果 id
   这一格**。`UbTierEffects` 把 UB 效果交给 `TieredEffects`，而 `TieredEffects` 只认分档效果：`ALLY_EFFECT` /
   `APPLY_EFFECT` 不是分档的，声明了也不会施加（最多一条报错日志）。
2. 挂在 `melee_hit` 钩子上是唯一能施加它的地方，但那会变成**每一次挥刀都免疫物理伤害** —— 那是另一个机制，
   不是「同一个机制弱一点」，而且比缺口更糟。

所以这一条落在 `ub.base.extra` / `ub.enhanced.extra` 上（**可见的缺口**，不是静默丢弃），并在
